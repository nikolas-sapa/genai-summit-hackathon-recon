# Paul Graham — Hackathon Reading List

Distilled notes live in the vault at `03-Resources/pg-brain/` (25 notes, indexed). These are the canonical links, ordered for the 36 hours ahead.

## Read before doors — the operating loop

| # | Essay | The one thing it gives you |
|---|---|---|
| 1 | [Startups in 13 Sentences](https://www.paulgraham.com/13sentences.html) | Whole playbook on one page: narrow user, launch fast, let the idea evolve |
| 2 | [Do Things That Don't Scale](https://www.paulgraham.com/ds.html) | Recruit users manually; Collison-install every demo |
| 3 | [How to Get Startup Ideas](https://www.paulgraham.com/ideas.html) | Pick problems you have; "live in the future, build what's missing" |
| 4 | [The 18 Mistakes That Kill Startups](https://www.paulgraham.com/startupmistakes.html) | #18 half-hearted effort + #8 slowness kill weekend projects |
| 5 | [Startup = Growth](https://www.paulgraham.com/growth.html) | One metric. Hackathon version: one demo that lands |

## PG → this event, mapped

| PG principle | Hackathon application |
|---|---|
| Do things that don't scale | Manually set up the judge demo; walk the artifact to their hands |
| Make something people want | Build for ONE named persona; "very disappointed" test on every feature |
| Launch fast | v1 in front of a mentor by Sat night, not Sun afternoon |
| Schlep blindness | The tedious multi-step real job = the challenge brief everyone dodges |
| Top idea in your mind | Logistics done before doors; the build owns the ambient slot all weekend |
| Superlinear returns | One polished interrogable demo > three features |
| Write ideas into words | One-page spec before first commit — catches scope gaps pre-code |
